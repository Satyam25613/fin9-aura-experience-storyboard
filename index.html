Evidence and assumptions

The sample makes the story concrete; it does not stand in for client data

The attached brief contains example values but no underlying portfolio file, market feed, risk snapshot, or goal-model output.

Scenario data status

Every firm, client record, date, metric, and source entry in this storyboard is illustrative or a product assumption. Replace the demo values with approved synthetic data and resolvable sources before a product demonstration. Do not treat them as Mr. Sharma’s real portfolio facts.

What the next demo needs to make the story verifiable

  • Market: review window, index return, leading and lagging sectors, and source links.
  • Portfolio: holdings, benchmark, returns, and contribution by holding or sector.
  • Risk: concentration, volatility, drawdown exposure, and risk-adjusted return with prior values.
  • Goals: probability method, assumptions, and what changed between 68% and 74%.
  • Meeting: an agreed sample discussion and the CRM fields / draft actions it should produce.
  • Sources: durable links or source IDs for every number that appears in the brief.
Product mechanics described in the source brief — validate before presenting as live behavior

The source brief describes a multi-step request classified as complex, planned on the user’s selected model, and split into dependency-aware tasks. Builder agents are preferred when they fit; up to five tasks can run concurrently. The final report streams from the selected model using its declared output ceiling. [5]

  • The brief says the read-only user_profile, Mem0 memories, COS lessons, and connected app context are included in agent prompts. Confirm what data is actually available to each task.
  • The brief says stopping a run cancels subagents and stops billing. Confirm cancellation and billing behavior before showing this as a guarantee.
  • The brief describes a shared cached system prompt across specialist tasks. This is an implementation note, not a user-facing proof point.
  • Interactive contents, expandable sections, evidence-linked charts, export, and follow-up offers are intended report behaviors; validate each in the product build.
